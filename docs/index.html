An agent team for your repo.
You merge until it earns more.

Agents find bugs, fix them and open PRs. Reviewers can't edit code, a guard hook blocks the shortcuts, and every miss a human catches becomes a test.

Install in Claude Code

/plugin marketplace add BbekShr/agent-org
/plugin install agent-org@agent-org

Then, inside your project:

/org-init
/<project>-ceo audit

About 4 seconds to install. /org-init reads the repo and works on a branch; audit is a read-only report. Stop anything with touch .claude/ceo/PAUSE.

One run, one team, start to finish.

You invoke the CEO. Read-only specialists find, one editor fixes, an adversarial board and the release gate judge, and a PR comes back to you. The team shown is what /org-init generates for a standard Next.js + Supabase app with a few bots, with the model each role runs on.

  1. Only builders write code.The CEO, the scouts, the reviewers and the release manager have no edit tools, so nobody grades their own work.
  2. Green gates are necessary, not sufficient.Every diff faces one reviewer per lens and the release gate together, on a frozen tree.
  3. Trust is earned.Promotion needs scorecard evidence and your say-so. A revert demotes the org on its own. Only you raise the level.

One CEO, ten modes.

/<project>-ceo <mode>. Every mode starts with preflight and ends with a report; apply modes end at a PR. The autonomy level decides which are open.

auditread-only · L0The report-only specialists write a board report. Nothing changes. Start here.
lightPR · L1 · defaultFast assess, then fix the top 1 to 3 items.
deepPR · L1Every specialist, every finding surfaced, fixes batched by owner.
<ID>PR · L1One named backlog item through the full pipeline.
request "<ask>"PR · L1Plain words from anyone, engineer or not, into a spec, then built.
triage "<bug>"records or PR · L0Reproduce the report on main first. Then confirm fixed, file it, or fix it.
discoverrecords · L0Hunt and file new bugs, one area and one lens at a time. discover fix also fixes them (L3).
rndrecords · L0Propose features and process changes with evidence. Never builds in the same run.
issuesrecords · L0Triage open GitHub issues, through the untrusted-input screen, into backlog items.
e2ePR · L1Drive the running app: find, fix, re-drive, ship. Local only, never production.

The last four are optional; /org-init asks which to include. Stop any run with touch .claude/ceo/PAUSE.

Autonomy is earned, one level at a time.

An org starts where its tests can prove a change correct. Promotion needs scorecard evidence and your approval. A revert demotes it on its own.

L0

Observe

Audits, bug discovery, proposals. Records only.

L1

Verify

Fix PRs, one at a time. You merge.

L2

Constrain

Adds scheduled headless runs.

L3

Parallelize

Parallel worktrees. Agents merge green PRs; you sample after.

L4

Cloud

Always-on routines, same gates.

Most orgs start at L1. Only you raise the level. Every level keeps the same gates and the same review board: a level unlocks capabilities, never shortcuts.

Measured, not claimed.

Agents are tested like code. /org-eval checks out the commit before a real fix and asks the agent to review it, then a different model scores the answer.
